# Cloudflare Pages Deployment

## Overview
Venom Atlas deploys as static assets generated by Astro. No production API server, ClickHouse, or Docker runtime is required.

## 1. Domain purchase or transfer
1. Use Cloudflare Registrar to purchase a domain, or transfer an existing domain into Cloudflare.
2. Ensure DNS is managed in the Cloudflare dashboard for the target zone.

## 2. Connect GitHub repository
1. In Cloudflare dashboard, open Workers & Pages.
2. Choose Create application > Pages > Connect to Git.
3. Authorize GitHub and select the `chrismac39/venom-atlas` repository.

## 3. Build settings
- Framework preset: Astro (or None/custom)
- Project root: `/`
- Build command: `pnpm build`
- Build output directory: `apps/web/dist`
- Node.js version: `20`
- pnpm version: `11.16.0`

## 4. Environment variables
- Optional: `PUBLIC_BASE_PATH` for non-root base paths (for GitHub Pages portability).
- No secrets are required for canonical public build output.

## 5. Preview deployments
- Every pull request branch can produce a preview deployment.
- Use preview URLs for route validation and provenance review.

## 6. Custom domain setup
1. Open Pages project > Custom domains.
2. Add the apex or subdomain.
3. Confirm DNS records generated by Cloudflare.
4. Wait for certificate provisioning.

## 7. HTTPS behavior
- Cloudflare Pages provisions TLS certificates automatically.
- Enforce HTTPS in Cloudflare zone settings if needed.

## 8. Rollback process
1. Open Pages deployment history.
2. Promote a prior successful deployment.
3. Re-run CI for a corrected branch if rollback is temporary.

## 9. GitHub Pages portability
- The site supports base-path override via `PUBLIC_BASE_PATH` in Astro config.
- For GitHub Pages, set `PUBLIC_BASE_PATH=/<repo-name>/` before build.
- Cloudflare root-domain deployment keeps default base `/`.
