# Static-Site Migration Plan

> **Historical migration plan — not an active roadmap.** The Astro static-first migration is in place; the architecture and deployment choices below describe the earlier migration baseline and target. The [README](../../README.md) describes the active architecture, and the [product audit and action plan](../quality/venomatlas-product-audit-and-action-plan.md) is the sole active roadmap. Milestone 0 (2026-09-08) selects GitHub Pages, superseding this plan's Cloudflare-first recommendation. Do not restore the archived backend or treat historical scientific blockers as a current validation report.

## Pre-migration architecture summary
- Monorepo with pnpm workspaces (`apps/*`, `packages/*`).
- `apps/web` is a React SPA (React Router) that consumes runtime API contracts.
- `apps/api` is a Fastify server with `clickhouse` or `mock` repository modes.
- ClickHouse schema and seeds are maintained in `database/*` and run through API db scripts.
- Domain and validation models are shared via `packages/domain` and `packages/schemas`.
- Visualization boundaries exist for Vega/Vega-Lite and molecular renderers (`3Dmol`, scaffolded Mol*).
- Scientific sample data exists in both TypeScript seed data and SQL seed data.

## Target architecture
- Static-first site generated by Astro in `apps/web`.
- Canonical authored content stored in `content-source/*` YAML.
- Build-time validation and normalization into static pages and JSON artifacts.
- React islands only for interactive elements (charts, molecular viewer, map controls, optional explorers).
- No production Fastify dependency, no production ClickHouse dependency, no production Docker dependency.

## Files retained
- `packages/domain`
- `packages/schemas`
- `packages/visualization-contracts`
- `apps/web/public` scientific and media assets (subject to validation gating)
- Existing visualization and molecular renderer components, adapted for islands

## Files adapted
- `apps/web` converted from SPA bootstrap to Astro file-based routing.
- Domain/schema models adapted for static content with slug-first identity.
- Tests adapted to static route rendering and no API runtime dependency.
- Root scripts adapted to static build/validate/test workflow.

## Files archived
- `apps/api` archived under `legacy/api`.
- `database` archived under `legacy/clickhouse`.
- legacy local startup scripts archived under `legacy/local-dev-scripts`.
- `docker-compose.yml` archived under `legacy/clickhouse/docker-compose.yml`.

## Files removed
- Placeholder `packages/config` package removed from active workspace.
- SPA runtime entry architecture (`main.tsx`, React Router app shell as canonical route source) removed from production path.

## Data migration plan
1. Convert `packages/domain/src/seedData.ts` sample content into YAML files under `content-source/*`.
2. Preserve evidence confidence and provisional labels exactly.
3. Build deterministic loaders and validation to produce normalized in-memory models.
4. Generate static JSON artifacts from the same canonical source.
5. Keep SQL seed data only in legacy archive for historical context.

## Route migration plan
- Replace client router canonical routes with Astro pages and dynamic route generation:
  - `/`
  - `/organisms`
  - `/organisms/[slug]`
  - `/organisms/[slug]/venom`
  - `/organisms/[slug]/geography`
  - `/toxins`
  - `/toxins/[slug]`
  - `/toxins/[slug]/mechanism`
  - `/toxins/[slug]/physiology`
  - `/effects`
  - `/sources`
  - `/about`
- Add static 404 handling.

## Test migration plan
- Keep and adapt existing unit tests for mechanism ordering, renderer selection, and Vega cleanup.
- Keep schema validation tests, updated to canonical loader output.
- Replace SPA smoke tests with static-route Playwright tests covering nested direct navigation and no `/api` calls.

## Deployment plan
- Primary target: Cloudflare Pages static deployment.
- Secondary portability: GitHub Pages via configurable Astro base path.
- CI builds and validates static output; no Docker/ClickHouse required.

## Known scientific and licensing blockers
- Public organism images currently lack complete redistribution proof and attribution metadata.
- Molecular structure SDF is placeholder/empty and must remain explicitly non-authoritative.
- 2D molecular SVG is placeholder and must remain labeled as such.
- Geography GeoJSON currently has no validated features.
